## Priority findings with exact code boundaries

### Cache is missing source work with an unproven native prerequisite

`actions/storage.cherri:6` declares `storeValue(text key, text value, bool ?global=false)`. Lines9 and12 expose read and delete. The iOS27 gate and generic native descriptor are not a typed archive implementation. No cache/retry entry occurs in the current canonical compiler-macro overlay or dispatcher.

A first read must have defined miss semantics before a lazy cache can safely decide to run its body. The existing delete/read fixture is a pending native question, not proof that missing keys return empty. Typed JSON encoded into Text could be a deliberate bounded future design, but it must preserve advertised Bool/Number/null/List/Dictionary distinctions, versioning and corruption handling and must not be presented as native arbitrary-object persistence. No new storage backend is needed.

Source and historical proof: `docs/apple-runtime/p10r15/cache-retry-storage-contract-audit-20261119.md`, `storage-cross-run-publication.md`, and `native-followup-20261119/storage-d430517-44428362458/`.

### Retry is not a source-only loop feature

`actions/web.cherri:110-149` maps GET/JSON/form/file bodies through downloadurl; `getURLHeaders` at line31 is another action/request. It cannot supply the status of the body request. Current native receipts establish HTTP body continuation, not status-as-value or catchability.

The retained 500/429/transport source is `52284f8ad179997bf35d41dde21a758dfc611059`. Runs44344880086 and44345197107 show body/continuation. Run44345223487 ends with Apple -1005 and no continuation. Existing bounded probe/readiness repairs are legitimate harness work, but they implement neither retry nor cache. Do not treat Alert+Stop, repeated underlying network connections, or a second headers request as a catch contract.

### General block semantics remain genuinely bounded

`internal/language/syntax/ast.go:400-405` explicitly defines an inline body without block parameters or escaping closures. `internal/language/analysis/scoped_blocks.go:10-73` accepts only measure, requires a literal label and final value, and rejects early yield or empty/void bodies. `internal/language/lower/scoped_blocks.go` uses the shared backend; this is reusable existing infrastructure, not a reason to create another parser.

`scoped_blocks_legacy.go` implements Legacy lexical scope, control frames, nested action materialization and result forwarding. `parser.go:890-891` still rejects a control-result declaration inside that scope with E_BLOCK_LEGACY_CONTROL_VALUE. `p15_scoped_blocks_legacy_test.go:266-282` intentionally asserts those unsupported forms. Existing declarations/control statements elsewhere must remain intact.

The collection limitation is independently explicit in `internal/language/analysis/loop_result_shape.go` and `p15_collect_list_boundary_test.go`. A rejected nested List is safer than corrupted output, but it is not completed nested-collection support.
