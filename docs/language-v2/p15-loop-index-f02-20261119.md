## Cause and bounded repair

The parser already accepted two spellings but discarded their distinction. Both `repeat i for N` and `repeat N as i` became the same AST; migration and formatting then rewrote the former to the latter. Both repeat and tuple-for lowering bound the user index directly to Apple's one-based `Repeat Index`. The prior Legacy parity correction had removed a subtraction from that shared path.

The parser now retains the existing Legacy spelling's index semantics, and both statement and expression formatting preserve it. Migration retains that spelling instead of silently changing its meaning. Modern `repeat N as i` and tuple `for (i, item) in values` emit the existing native Math subtraction with operand one, then capture that exact action output in the lexical index variable inside the owning loop.

| Source boundary | Index behavior |
| --- | --- |
| Modern `repeat N as i` | Zero-based named index |
| Tuple `for (i, item) in values` | Zero-based named index |
| Existing Legacy `repeat i for N` | Native one-based named index |
| Explicit `RepeatIndex`, `RepeatIndex2`, and numbered native globals | Native one-based references |
| Omitted or `_` index | No synthetic index conversion |

Loop depth now begins after count or iterable evaluation. An iterable-producing loop executes before its consuming loop, so it must not reference a nonexistent extra native nesting level. The producer and consumer case is checked explicitly.

No native action catalog, golden runtime output, original public fixture, parity normalization policy, or acceptance contract changed. One existing migration formatting assertion now requires the preserved Legacy spelling; the one-based behavior is independently checked in emitted production parameters and the unchanged original repeats fixture.
