# Independent File Extension control

The earlier signed file-name-binding run remains a failure against its unchanged oracle. All three routes reported the same name stem with preserved JSON text. That does not establish whether the extension was absent.

The new fixture asks the native File Extension property separately and reconstructs the complete name. It also checks the renamed value's type against the decoded File, exact Base64 bytes, and JSON text. Get Name, File Extension and the byte check all consume the same renamed File UUID; Set Name consumes a real Base64 Decode File. It does not call the production debug export macro and cannot by itself establish that macro's correctness.

The canonical action/property definitions are retained in the Apple macOS 27 action metadata. Get Name has no extension option there. This diagnostic changes neither the old expected marker nor the production export implementation.
